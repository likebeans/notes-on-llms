# 关于本站

Notes on LLMs 是一份面向中文读者的大模型学习手册。它更像“持续整理的研究/工程笔记”，而不是一次写完的教材。

## 适合谁

- 想从 Prompt、RAG、Agent 开始做 LLM 应用的开发者。
- 想补训练、微调、对齐、评估和多模态基础的算法工程师。
- 正在准备 LLM 应用/算法/平台方向面试的人。
- 已经做过一些 AI demo，但想把它们推向更可靠系统的人。

## 作者视角

本站采用“工程可落地优先”的组织方式：先解释问题和失败模式，再补论文、架构和实现细节。对于快速变化的模型/API，页面会尽量标出技术版本和内容状态。

## 内容状态

| 状态 | 含义 |
| --- | --- |
| `verified` | 已按当前资料复核，适合作为主线引用 |
| `needs-review` | 已整理但仍需继续校验，阅读时注意技术版本 |
| `opinion` | 包含作者经验判断，不等同于标准答案 |
| `historical` | 保留历史背景或旧方案，不代表当前推荐实践 |
| `draft` | 草稿，不进入公开主线 |

## 来源政策

- 概念定义优先参考论文、官方文档、官方博客和项目仓库。
- 工程建议会结合真实项目经验，但应配合评估样本验证。
- 涉及 API、模型版本、价格和发布状态的内容容易过期，需要按日期复核。
- 不确定的信息会保持 `needs-review`，避免把“看起来合理”写成事实。

## 更新流程

1. 先补齐 frontmatter：标题、模块、状态、更新时间和技术版本。
2. 再整理正文：目标、核心概念、实践步骤、常见失败。
3. 对关键资源补官方链接或原始论文。
4. 运行内容检查和站点构建。
5. 重要页面进入后续复核队列。
