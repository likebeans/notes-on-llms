# 参考手册

这里放的是“做事时会反复翻”的内容：术语、清单、指标和模板。它不替代完整文章，而是帮你在写方案、做评审、准备面试时快速对齐语言。

建议把这一组页面当作“上线前的桌面工具”：术语表负责统一语言，Checklist 负责暴露遗漏，指标页负责避免只看最终答案，模板页负责让方案、实验和复盘有一致格式。

## 四个集合

| 集合 | 用途 | 入口 |
| --- | --- | --- |
| 术语表 | 快速确认概念定义、关联页面和常见误解 | [术语表](/reference/glossary) |
| Checklist | 评审 Prompt、RAG、Agent、微调和发布风险 | [Checklist](/reference/checklists) |
| 评估指标 | 选择 RAG、生成、Agent、训练和安全指标 | [评估指标](/reference/metrics) |
| 模板 | 复用 Prompt、RAG 回答、工具 schema、实验记录 | [模板](/reference/templates) |

## 怎么用

- 写方案前：先过术语表，避免团队说的是不同东西。
- 开发前：用 checklist 定义“不做什么”和“失败怎么算”。
- 上线前：用指标页确认至少有一个回归评估入口。
- 复盘时：用模板记录失败样本和下一步实验。

## 从一次变更开始使用

假设你准备给知识库增加 rerank：先用术语表确认召回与重排的边界，用指标页选定候选召回率、排序质量和端到端答案指标；把固定问题、配置和结果填入实验模板，再用检查清单核对权限、预算与回滚。四类资料应一起支撑一项具体决策。

遇到同名但算法不同的指标，优先写出公式和分母；遇到可直接复制的模板，先核对它是设计草图还是某个 SDK 的实际格式。
